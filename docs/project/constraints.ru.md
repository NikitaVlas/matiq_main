# Ограничения проекта MATIQ

## Технические ограничения

- `TC-001`: Проект реализуется как TypeScript-монорепозиторий.
- `TC-002`: Frontend использует Next.js и React.
- `TC-003`: Backend использует NestJS как модульный монолит.
- `TC-004`: Основное хранилище — одна PostgreSQL с Prisma.
- `TC-005`: Публичное взаимодействие web и API выполняется через REST.
- `TC-006`: HTTP-контракт описывается OpenAPI.
- `TC-007`: Фоновые задачи выполняются отдельным worker через Redis и BullMQ.
- `TC-008`: Workspace управляется pnpm и Turborepo.
- `TC-009`: Локальная инфраструктура должна поддерживать Docker Compose.
- `TC-010`: Конкретные production-провайдеры выбираются только после отдельного
  согласования.

## Продуктовые ограничения

- `PC-001`: Первый рынок — Германия.
- `PC-002`: Основной язык всех интерфейсов — немецкий.
- `PC-003`: Поддерживаются BJJ Gi и No-Gi Grappling.
- `PC-004`: Существует только веб-платформа без отдельного лендинга.
- `PC-005`: Нативные мобильные приложения не входят в первую версию.
- `PC-006`: Тренеры не загружают и не редактируют контент.
- `PC-007`: AI объясняет результат, но не определяет методологию.

## Ограничения безопасности и конфиденциальности

- `SC-001`: Основные пользовательские данные и резервные копии хранятся в ЕС.
- `SC-002`: Международный внешний сервис требует отдельного согласования и
  проверки GDPR, DPA и передачи данных за пределы ЕС.
- `SC-003`: Авторизация и permissions проверяются на сервере.
- `SC-004`: Видео не публикуется как общедоступный исходный файл.
- `SC-005`: Медицинские диагнозы в первой версии не собираются.
- `SC-006`: Секреты и платёжные данные не попадают в клиентский код, журналы
  или документацию.
- `SC-007`: MFA обязательна для `Admin` и `Editor`.
- `SC-008`: Критичные административные действия требуют повторной
  аутентификации.

## Ограничения совместимости

- `CC-001`: Первая версия поддерживает desktop, tablet и mobile web.
- `CC-002`: Минимальные версии браузеров пока не определены.
- `CC-003`: Публичный API нельзя несовместимо изменять без явного согласования.

## Ограничения времени и бюджета

- Сроки не определены.
- Бюджет инфраструктуры не определён.

## Запрещённые изменения

- Микросервисы без утверждённого ADR.
- Дублирование бизнес-логики между утверждёнными User API и Admin API.
- Прямой доступ frontend к PostgreSQL.
- Перенос бизнес-логики в HTTP-контроллеры.
- Самостоятельная публикация контента тренерами.
- Сбор медицинских диагнозов в первой версии.
- Использование внешнего production-сервиса без согласования.

## Решения, требующие согласования

- Изменение публичного API.
- Изменение аутентификации или авторизации.
- Добавление production-зависимости.
- Выбор hosting, video, email, AI или другого внешнего провайдера.
- Платежи, возвраты, налоги и действия в Stripe.
- Автоматизация выплат тренерам.
- Передача пользовательских данных за пределы ЕС.
- Деструктивная миграция или удаление данных.
- Развёртывание и действия в production.

## Открытые вопросы

- Production hosting и ожидаемый бюджет.
- Поддерживаемые браузеры.
- Целевые показатели производительности и доступности.
- Политики хранения, резервного копирования и удаления данных.
- Конкретные требования к защите видео.
