# ADR-0007: Общий механизм отключения продления

## Решение

Согласовано владельцем 2026-09-04. API и worker используют общий application
service в packages/backend, порт провайдера и PostgreSQL-хранилище операций.
Хосты не импортируют друг друга. Production provider не выбирается.

## План реализации

1. Добавить таблицу устойчивых операций отключения продления аддитивной миграцией.
2. Реализовать создание с проверкой владельца, временный захват и подтверждение.
3. Сначала сверять состояние провайдера, затем запрашивать отмену. После timeout
   повтор начинается со сверки. Отсутствие провайдера не считается успехом.
   Сырые ошибки не сохраняются; ID операции служит ключом идемпотентности.
4. Добавить worker adapter и точку входа application API; существующий публичный
   cancellation API пока не менять до подключения контрактов планирования удаления.
5. Проверить unit-тестами и на синтетическом PostgreSQL без реальных платежей.

## Ограничения

Внешние вызовы вне транзакций. Захват истекает; старый исполнитель не может
подтвердить результат. Операция хранит только ссылку на локальную подписку,
без копирования идентификаторов провайдера. Завершённая техническая запись
хранится 30 дней; ожидающие операции требуют сверки/эскалации, не тихого удаления.
Это не завершает удаление аккаунта и не стирает обязательные финансовые документы.
UI и хранение расписания подключены; webhook ставит сверку в очередь,
resume проверяет расписание и ожидающие операции.
Новые публичные действия требуют ownership, reauthentication и CSRF.
UI не должен считать принятую/ожидающую операцию успешной отменой.

## Эксплуатационные ограничения

Миграция требуется до запуска обновлённого worker. Рабочая база этим изменением
не мигрировалась. Polling раз в минуту, batch 25, lease 2 минуты, повтор через
5 минут. После 12 неудачных попыток автоматические повторы прекращаются,
reviewRequired в безопасном журнале показывает необходимость ручной сверки.
Операции без существующей подписки также требуют ручной сверки. Подключение
мониторинга/эскалации и ограничений времени сетевого адаптера — production gates.
Нет FK на Subscription: незавершённое свидетельство не удаляется каскадно;
завершённые технические операции удаляются через 30 дней. Политика очистки
неразрешённых операций после расследования требует отдельного решения.
После rollback кода оставить аддитивную таблицу, не удалять живые операции.
Проверки перед resume не обеспечивают атомарность удалённого вызова с новым
расписанием. Гонки provider events и восстановление изменений после backup
остаются release gates вместе с подключением реального адаптера.
